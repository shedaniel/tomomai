## 6月のアップデート：ローリングリリースへ

tomomai のリリース方法を、小規模ながらも重要な形で変えます。これからは**ローリングリリース（順次公開）**へ切り替えます。新機能や改善は、毎月決まった日にまとめるのではなく、完成したタイミングで随時リリースしていきます。これで、機能が完成してから皆さんの手元に届くまでのタイムラグがぐっと短くなります。

月末の投稿はこれからも続けますが、役割が変わります。これからは「発表の場」ではなく、その月にリリースした内容を振り返る**まとめ**になります（本記事がその第1弾です）。今月は新しいサインイン方式、Discord ボットの大型アップデート、そしてサイトをより速く安く動かすための裏側の改善が盛りだくさんです。

## 新機能：X と Passkeys でサインイン

2つの新しいサインイン方式、**X（Twitter）** と **Passkeys** を導入しました。どちらも実はしばらく前に実装が完了していましたが、これらをカバーする利用規約とプライバシーポリシーの改定を待つ必要がありました。本日バージョン管理された新しいポリシーが公開され、どちらもすべてのユーザーに解放されています。（ローリングリリースモデルの分かりやすい実例でもあります。コード自体は5月末に完成していましたが、法務面の更新を待っての公開となりました。）

**Passkeys。** パスワードの代わりに、お使いのデバイスの Passkey（Face ID、Touch ID、Windows Hello、またはハードウェアキー）でサインイン・新規登録できるようになりました。Passkeys はフィッシングに強く、デバイスに紐付けられているため、パスワードよりも扱いやすく、かつ安全です。設定画面から複数の Passkey を追加・管理できるほか、登録時には Bot 対策として Proof-of-Work 方式の CAPTCHA で保護しています。

![X と Passkeys でサインイン](/posts/2026-06-30-june-update/sign-in.webp)

**X でサインイン。** Discord に加えて X（Twitter）アカウントの連携にも対応しました。どちらのアカウントからでもサインインできます。連携の設定や解除は、いつでも設定画面から行えます。

### 利用規約とプライバシーポリシーの刷新

これらの新機能を有効にするにあたり、同意フローを備えた**バージョン管理型の新しい利用規約・プライバシーポリシー**へ刷新しました。以前から tomomai をご利用の方は、次に重要な操作を行う際に新バージョンへの再同意を求められます。システム側で最後に同意したバージョンを記録しているため、実際に変更があったときだけ再度お願いします。

これにより、**Developer API**（API キー、OAuth アプリケーション、開発者ポータル）の提供に向けた土台も整いました。詳細は追ってお知らせします。

新しくなった[利用規約](/tos)と[プライバシーポリシー](/privacy)をご確認ください。

## Discord ボット：リージョンオプション、鮮度プロンプト、i18n

今月は Discord ボットの強化にかなりのリソースを割きました。

**1アクションにつき1コマンドへ集約。** 従来のリージョン別のコマンドペアは廃止しました。`/fetch`、`/profile`、`/recents`、`/recommend`、`/daily` はすべて単一のコマンドに統合され、**デフォルトでお使いの設定リージョンが適用**されます。別のリージョンで上書きしたい場合は、オプションの `region` を指定するだけで OK です。CN サポートもボット全体に行き渡っています。

![Discord のリージョンオプション](/posts/2026-06-30-june-update/discord-region.webp)

**データの「鮮度」を考慮した挙動。** 対象リージョンの最新スナップショットが1時間以上前の場合、ボットは実行前に確認を求めるようになりました。**Continue**（既存のデータでそのまま実行）か、**Refetch and continue**（先に新しいデータを再取得してから実行）かを選べます。また、これらのコマンドにオプションの `fetch` が追加され、確認なしで強制的に再取得して実行することも可能です。

![Discord の鮮度プロンプト](/posts/2026-06-30-june-update/discord-staleness.webp)

**メッセージの完全ローカライズ。** ボットの応答が Discord クライアントの言語設定と連動するようになり、サポートするすべてのロケール（`en-US`、`en-GB`、`ja`、`zh-CN`、`zh-TW`、`ko`）の翻訳が完了しています。

さらに、これらのコマンドはすべての操作コンテキスト（サーバー、ボットとの DM、ユーザー間の DM）に登録され、どこからでも呼び出せるようになりました。

## 難易度キャップ付きの予約プロフィール

理論上の最高レーティングを表示する [`max`](/profile/max) 予約プロフィールはお馴染みかと思いますが、今回あらたに難易度でキャップをかけたバリエーションを追加しました：[`maxbas`](/profile/maxbas)、[`maxadv`](/profile/maxadv)、[`maxexp`](/profile/maxexp)、[`maxmas`](/profile/maxmas)、[`maxrem`](/profile/maxrem) です。それぞれ、指定した難易度以下の譜面だけを使って理論上の最高レーティングを算出します（宴会場譜面はすべてのリージョンで除外）。「もし特定の難易度帯が存在しなかったら、自分はどこに着地するか」を試算するのに便利です。

![難易度キャップ付きプロフィール](/posts/2026-06-30-june-update/reserved-profiles.webp)

## UI のブラッシュアップ：MD3 サーフェス、グラス、ピル

サイト全体で Material 3 の見直しを行いました：

- テーマに **tonal surfaces** と container のカラーロールを追加し、フローティングオーバーレイ（モーダル、ダイアログ、ドロップダウン）向けに glass-surface ユーティリティを新設しました。
- ボタンとバッジは**ピル型**に統一し、新たに tonal と tertiary のバリアントを追加しました。
- データバナー内のレーティングとバージョンのチップを、より洗練されたバッジに差し替えました。
- Inter に stylistic sets と tabular numerics（等幅数字）を適用しました。

![MD3 グラスとピル](/posts/2026-06-30-june-update/md3-ui.webp)

さらに、リアルタイムのビルド情報を表示する新しい**サイトフッター**も実装しました。バージョン、ビルドのタイムスタンプ、元となったコミットが表示されます。完全に自動化されており、変更履歴の投稿とビルドパイプライン自身から駆動されるため、手動での更新忘れも起きません。

![バージョンフッター](/posts/2026-06-30-june-update/version-footer.webp)

## 目に見えないところ

6月の大部分はパフォーマンス改善とインフラの最適化に費やされました。tomomai の見た目は変わりませんが、サイトはより速く、より安く動くようになります。

### `[locale]` ルーティングによる静的キャッシュ

ロケールを URL（`/en/...`）に移し、リクエストごとの Cookie 読み取りではなくキャッシュキーの一部として扱えるようにしました。これによりアプリの大部分が動的処理からキャッシュ可能へと切り替わり、**静的ページが 104 から 440 へと大幅に増加**しました。カタログ（`/db/songs`、楽曲詳細）や公開プロフィールは、アクセスごとに再レンダリングされる代わりに ISR（一度生成してキャッシュから配信）へ移行しています。

その後のチューニングでコスト削減はさらに進みました。ISR の有効ウィンドウを広げ、カタログにブラウザのキャッシュヘッダーを追加したことで、リピーターは1時間キャッシュされた HTML を再利用し、その後1日間は stale-while-revalidate で対応します。また、楽曲詳細ルートの ISR 書き込みコストは、カタログ全体を各詳細ページにシリアライズするのをやめ、楽曲リストを共有レイアウト側に持たせることで **約10分の1** に削減されました。ついでに、譜面ドロワーを開閉した際にリストがアンマウントされて再読み込みされる挙動も解消しています。

さらに、初回ペイントの前に小さなブロッキング `<script>` が保存済みテーマを即座に適用するようになり、読み込み時に間違ったテーマが一瞬表示されるちらつきも解消されました。

### 画像レンダリングの分離

すべての画像レンダリング（エクスポート画像、last-credit、daily-plays）をメインアプリから完全に切り離し、専用の `apps/render` サービスへ移しました。出力される画像のピクセル品質はこれまでと完全に同一です。大きなメリットは、リクエスト CPU の最も重い部分（約78%）を占める WebP エンコード処理が Vercel 関数を圧迫しなくなり、レンダリングされたバイト数も Vercel のエグレスにカウントされなくなった点です。メインアプリは引き続き認証の境界として振る舞い、短命なトークンを発行して処理を引き渡すだけなので、画像データそのものがメインアプリを経由することはありません。

### コスト削減

- **ジャケット：** これまで多くの楽曲ジャケットが `maimaidx.jp` に置かれたままで、サイズやフォーマットごとに Vercel 側で再最適化が走っていました。今回マイグレーションの対象範囲を広げてバックフィルを行い、**29,071 行**を自社の R2 CDN へ移しました。これによりジャケットは Vercel の最適化パスから100%外れています。
- **アルバム：** ユーザーごとのストレージ上限を 25 MB から **8 MB** に引き下げ、新規アップロードは AVIF q40 に自動再エンコードされるようにしました（この種のリザルト画面の写真であれば、画質の劣化はほぼ判別できません）。既存のアルバムにも同じ最適化を一括で適用し、アルバム全体のストレージ容量は **750 MB から 268 MB（約64%削減）** になりました。なお、この改定で新しい上限を超えてしまったユーザーはいませんでした。
