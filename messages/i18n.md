# 🌐 i18n Guidelines

> Guidelines for contributing translations to **tomomai ともマイ**

*Last updated: 2026‑05‑07*

---

## 🧭 Overview

`tomomai ともマイ` supports the following locales:

| Locale code | Language | Target audience |
| :--- | :--- | :--- |
| `en` | English (US) | Base / reference language |
| `en-GB` | English (UK) | Base / reference language |
| `ja` | Japanese | Japanese players |
| `zh‑TW` | Traditional Chinese | Taiwan players |
| `zh‑HK` | Traditional Chinese (Hong Kong) | Hong Kong players |
| `zh‑CN` | Simplified Chinese | Mainland China players |
| `zh‑SG` | Simplified Chinese (Singapore / Malaysia) | Singapore + Malaysia players |

The **English version is always the authoritative reference.**  
All other localizations should preserve its intent and tone but adapt phrasing to each region’s natural written style.

> **Note on `zh‑SG`:** This locale is a **union of Singapore and Malaysia** Mandarin (新马华语 / 大马华语). The two regions share enough vocabulary, written conventions, and English/Hokkien/Malay loanword patterns that maintaining separate `zh‑SG` and `zh‑MY` files would mostly duplicate strings. If meaningful divergence emerges later, split into `zh‑SG` and `zh‑MY` then.

## 🗣️ Tone & Style

### General personality
- **Friendly, community‑oriented, but not childish**  
- Clear, concise phrasing appropriate for rhythm‑game players
- Avoid corporate or overly technical phrasing unless context requires

### Don’t translate globally recognized game terms

Keep in English for all locales:
`FC`, `FS`, `B15`, `B35`, `maimai`, `DX NET`, **`Rating`**

### Tone patterns by language

| Locale | Style | Example tone |
|---------|-------|---------------|
| 🇬🇧 `en` | Neutral‑friendly | “Track and analyze your maimai scores with friends.” |
| 🇯🇵 `ja` | Polite‑casual (like SEGA UI) | “設定を保存しました！” / “準備中…” |
| 🇹🇼 `zh‑TW` | Friendly written Chinese with full‑width punctuation | “點擊「匯入新資料」來匯入你的 maimai 成績。” |
| 🇭🇰 `zh‑HK` | Friendly written Chinese, Hong Kong terminology, full‑width punctuation | “點擊「匯入新資料」以匯入你的 maimai 成績。” |
| 🇨🇳 `zh‑CN` | Natural Simplified Chinese for web | “点击“导入新数据”来导入 maimai 成绩。” |
| 🇸🇬 `zh‑SG` | Simplified Chinese with SG/MY vocabulary | “点击“导入新数据”以导入你的 maimai 成绩。” |

## 🔤 Placeholders and Links

When English uses interpolations or links split across two keys:

```json
"accessibleBy": "Accessible by ",
"accessibleByEnd": "!"
```

Each locale should wrap the link text **naturally**. Examples:

| Locale | Result |
|--------|---------|
| zh‑CN | 可通过 \<a>公开链接\</a> 访问！ |
| zh‑SG | 可透过 \<a>公开链接\</a> 访问！ |
| zh‑TW | 可透過 \<a>公開連結\</a> 存取！ |
| zh‑HK | 可透過 \<a>公開連結\</a> 存取！ |
| ja | \<a>公開リンク\</a> から閲覧できます！ |

**Always include leading / trailing spaces** as needed so link text doesn’t collide with sentences.

## 📐 Layout & Space Considerations
- Japanese text is typically 10–15 % longer than English — check for button truncation.  
- Chinese strings often omit subjects for brevity.  

---

## 🧰 Technical Guidelines

- JSON files must be UTF‑8, double‑quoted keys/values.  
- Keep identical key structure in all locale files.  
- Validate via linting before committing.

---

## 🛠️ General Technical Considerations

  * **Variable Names in Text:** Avoid breaking variable names (e.g., `{userName}`) across lines or modifying their case/spelling, as this will cause runtime errors.
  * **HTML Entities:** Do not use HTML entities (e.g., $\text{&apos;}$ or $\text{&quot;}$) for basic punctuation; use the character itself (e.g., $\\text{'} $ or $\text{"}$). The only exception is non-breaking space ($\text{&nbsp;}$) when required for layout.

## 💭 Notes on Key Language Choices

### Japanese (ja)
- Prefer friendly plain forms (“設定を保存しました！”).  
- “準備中…” is standard “coming soon”.

### Traditional Chinese (Taiwan, zh‑TW)
- Full‑width punctuation（：，「」）.  
- Semi‑formal tone like Taiwanese web UIs.
- **Avoid the formal second-person pronoun $\text{您}$ (nǐn). Use $\text{你}$ (nǐ) instead to maintain a friendly, casual tone.**

### Traditional Chinese (Hong Kong, zh‑HK)
- Friendly written Chinese, no spoken Cantonese particles.
- **Avoid the formal second-person pronoun $\text{您}$ (nǐn). Use $\text{你}$ (nǐ) instead to maintain a friendly, casual tone.**
- **Use Hong Kong vocabulary** — common TW → HK swaps to be aware of:
    * 隱私 → **私隱**
    * 軟體 → **軟件**
    * 專案 → **項目**
    * 大陸（區）→ **內地（區）**
    * 使用者（名稱）→ **用戶（名稱）**
    * 工作階段 → **登入工作階段**
    * 臉部 → **面部**
    * 社群 → **社交**
    * 分布 → **分佈**
    * 今天 → **今日**
    * 謝謝 → **多謝**
    * 販售 / 出售給 → **出售予**
- **「連結」 for "link"** (not 「鏈接」). 鏈接 is a PRC-influenced form sometimes seen in HK; the codebase uses 連結 throughout, matching TW and the broader written-HK convention.
- **Keep `Rating` in English** (not 「R 值」) and **`Cookies`** (not 「權杖」).
- **Connector words / phrasing patterns:**
    * Use **「以」** not **「來」** for purpose connectors: 「點擊⋯⋯**以**匯入」, not 「⋯⋯**來**匯入」.
    * Use **「透過」**, never 「通過」, for "via / through".
    * Prefer **「於 {date} 建立」** over 「建立於 {date}」 (HK-style word order).
    * **「其後」** over 「之後」 in formal-leaning text where natural.
- **Punctuation:**
    * Use **「……」** (full-width ellipsis), not `...`, for trailing-action labels (e.g. 「載入中……」, 「建立中……」).
    * Keep full‑width punctuation（：，「」）.
- “點擊” instead of “按一下”; it reads naturally for HK web UIs.

### Simplified Chinese (zh‑CN)
- Use succinct modern phrasing (“点击…来…”).  
- Keep auth terms short (“登录凭证”, “Cookies”).  
- Avoid rare literary style.
- **Politeness:** Using the polite second-person pronoun $\text{您}$ (nǐn) is acceptable if the context is semi-formal (e.g., error messages, settings, privacy), but **$\text{你}$ (nǐ) is often preferred for casual prompts and greetings.**
- **Avoid TW residues.** This file was originally seeded from `zh‑TW` and re‑localized; watch for these specific TW carry‑overs when adding new strings:
    * 档案 (used for "profile") → **主页 / 个人主页**
    * 帐户 / 帐号 → **账户 / 账号** (modern simplified standard uses 账, not 帐)
    * 登入 → **登录**
    * 取得 → **获取**
    * 应用程式 → **应用程序**
    * 装置 → **设备**
    * 透过 → **通过**
    * 资料 (for technical "data") → **数据**; (for "info") → **信息** — *but* `个人资料` is acceptable PRC usage, keep as‑is.

### Simplified Chinese (Singapore / Malaysia, zh‑SG)
- **Audience:** This locale serves both **Singapore (新加坡华语)** and **Malaysia (大马华语)** Mandarin users. The two regions share enough vocabulary, English/Hokkien/Malay loanword patterns, and written conventions that they're unified into a single file. Split only if meaningful divergence emerges.
- **Standpoint:** SG/MY simplified Chinese keeps PRC simplified characters but retains older / TW‑shared vocabulary that PRC Putonghua standardization replaced in the 1980s.
- **Use $\text{你}$ (nǐ), not $\text{您}$ (nǐn).** Standardize on the casual register; SG/MY web UIs lean less formal than PRC.
- **Vocabulary differs from `zh‑CN` — use SG/MY forms:**
    * 登录 → **登入**
    * 创建 → **建立**
    * 当前 → **目前**
    * 信息 → **资讯**
    * 添加 → **新增**
    * 图标 → **图示**
    * 应用程序 → **应用程式**
    * 设备 → **装置**
- **Shared with `zh‑CN` (modern simplified standard):**
    * 档案 (for profile) → **主页 / 个人主页**
    * 帐户 / 帐号 → **账户 / 账号**
- **Keep TW‑shared terms** (do *not* PRC‑ify these): 资料, 取得, 透过, 设定 — all natural in SG/MY.
- **Punctuation: full‑width**（：，“”）— matches the older‑education‑system convention still common in SG/MY local media and aligns naturally with content copied/converted from TW/HK sources. Half‑width punctuation is only used inside technical tokens (URL paths, code identifiers, `Re:Master` difficulty name, etc.), never in natural‑language sentences.

## ➕ Adding a New Language

When adding a new locale (e.g. `fr`), update **all** of the following:

1. **`messages/<code>.json`** — copy `messages/en.json` as the seed and translate values. Keep the key structure identical.
2. **`src/i18n/locale.ts`** — add the code to both the `Locale` union type and the `locales` array.
3. **`src/lib/utils.ts`** — add an entry to `getLanguages()` with `value`, `label: t('settings.language.<code>')`, and a 2‑letter `code` used for the flag/region badge.
4. **`messages/en.json` and every other locale file** — add the new label under `settings.language.<code>` (e.g. `"fr": "Français"`). Each existing locale must include this label so the language picker renders correctly when that locale is active.
5. **`src/lib/i18n/translation-stats.ts`** — import the new JSON at the top and add an entry to `TRANSLATION_STATS` so the About dialog shows its coverage.
6. **`src/lib/db/types.ts`** — add the code wherever the locale list is referenced (search for an existing locale like `'en-GB'`).
7. **`src/components/post-locale-switcher.tsx`** — add the locale to the displayed switcher list if it filters locales explicitly.
8. **`src/app/globals.css`** — for any locale that needs a CJK font (Chinese / Japanese / Korean / etc.), add `body:has([lang="<code>"])` and `html[lang="<code>"] body` selectors to the appropriate font-family group. Otherwise the locale falls through to the default (currently `NotoSansJP`), which paints CJK characters with the wrong regional glyph shapes (e.g. a SC locale showing JP-style glyphs).
    * Traditional Chinese variants → `NotoSansTC`
    * Simplified Chinese variants → `NotoSansSC`
    * Japanese / Korean / Latin → default (`NotoSansJP` group)
    * If a new font family is needed, add `@font-face` chunks under `src/app/cjk-fonts.css` (auto-generated; see `scripts/subset-fonts.sh` and `docs/FONTS.md`).
9. **`src/lib/og.tsx`** — if the locale uses CJK characters, add it to the `needsTC` / `needsSC` (or new) check around line 44 so OG image generation loads the right font subset.
10. **`src/lib/posts.ts`** — if the locale should fall back to another locale for blog posts (e.g. via OpenCC conversion), update `getLocaleFallbackChain()` and the conversion logic in `getAllPostsMeta` / `getPostBySlug`, plus `getAvailableTranslations()` to expose the virtual locale.

### Verification

- Run `pnpm tsc --noEmit` — the `Locale` union must be consistent across all references.
- Run `pnpm dev`, open Settings → Language, switch to the new locale, and confirm the UI renders without missing‑key warnings in the console.
- **Inspect a CJK character in DevTools** to confirm the correct font is applied (e.g. `NotoSansSC` for SC locales, `NotoSansTC` for TC locales). Wrong-region glyphs are easy to miss visually but very obvious to native readers.
- Open the About dialog and verify the new locale appears in the Translations section with the correct percentage.
